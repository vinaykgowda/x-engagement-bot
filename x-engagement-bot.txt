📊 Database Schema
Global Tables (Cross-Server):
1. global_users           - Global user profiles (one per user)
2. global_twitter_profiles - Twitter profiles (unique globally)
3. global_wallets         - Solana wallets
Server-Specific Tables:
4. servers                - Server configurations
5. server_access_codes    - Access codes for onboarding
6. server_engagements     - Engagement campaigns (per server)
7. server_user_engagements - User engagement tracking (per server)
8. server_points          - User points (per server)
9. server_rewards         - Reward configs (per server)
10. server_raid_config    - Raid channel config (per server)
11. server_raid_tweets    - Raid tweet tracking (per server)
12. server_transactions   - Transaction history (per server)

```
## **💡 How It All Works Together:**

### **User Journey:**
```
1. User joins server with bot
   → guildCreate.js sets up server

2. User links Twitter profile
   → /set-profile command
   → interactionCreate.js → Opens modal
   → User submits → profileModal.js processes

3. Admin posts engagement
   → /post-engagement command
   → Creates campaign with buttons

4. User clicks "Check Engagement"
   → Button click → interactionCreate.js
   → checkButton.js verifies via Python scraper
   → Points awarded if complete

5. User posts raid tweet
   → messageCreate.js detects URL
   → Validates & awards automatically
   → Posts to announcement channel

6. Background: Every 5 minutes
   → ready.js checks expired campaigns
   → Auto-deactivates old engagements
